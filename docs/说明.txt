使用方法

1. 用 Chrome / Edge 打开 index.html。已有页面直接刷新。
2. 保持相同文件路径及浏览器，继续读取原先保存的外观参数。
3. 从底部上拉或点击按钮展开；下滑横条、点击 ×、点击外部或 Esc 收起。
4. 右上角「玻璃参数」实时调节外观，可导出 JSON 备份、导入恢复。

渲染引擎

默认「自动 · WebGL2 缓存折射」：底板生成纹理后复用，滚动只改变采样位置。
没有滚动时关闭折射或切换毛玻璃的逻辑。玻璃内个人信息仍是 DOM 文字。
准备纹理或 GPU 异常时，Chromium 下使用完整原版 SVG 折射。
参数框可切到「原版 SVG · 对照」，在相同参数下直接比较。
初始化、窗口尺寸/字体/底板内容改变时会重建纹理；普通滚动不重建。
所有资源内置，无依赖、无外部资源请求、无需启动服务。

文件

index.html：日常使用的优化版。
baseline-svg.html：优化前完整归档。单独打开时的参数存储可能与入口不同。
性能实验室.html：可重复的隐藏/展开受控滚动测试、GPU计时和故障回退测试。
工程日志.txt：每轮路线、工作、结果、淘汰原因与尚未验证的限制。
测量结果.json：有效测试的原始数字、视觉比对统计和解释。

性能实验室

如需严格比较自己的参数，先在 index.html 导出，再在实验室导入。
分别选择自动引擎和原版 SVG，在相同窗口尺寸、缩放和参数下点击「测试展开」。
不要在一次测量中途改变尺寸或引擎。测试中页面会自动往返滚动。
「连续采样」需在预热提示结束后手动滚动，结果只代表采样期间的负载。
「模拟 GPU 丢失」只用于确认完整 SVG 回退；刷新实验室可重新初始化 GPU。
「底板原生捕获对照」用于核对底板缓存画面，再次点击关闭。

数字的边界

rAF 间隔是 JS 调度指标，不等同屏幕实际呈现帧率。
GPU timer 只计本程序着色器绘制，不包含浏览器最终合成、显示器刷新和输入延迟。
已验证默认参数下自有 GPU 绘制、缓存复用、参数极值和交互，不能保证每台设备稳定120fps。
缓存纹理和原生 DOM 存在字体抗锯齿/亚像素差异，强折射零模糊时尤其可见；保留原版对照。
原生合成线程与 WebGL 主线程在压力下的逐帧同步尚未取得显示级性能轨迹验证，不能宣称绝无单帧错位。
实验室浏览器验证使用本地 HTTP；工具禁止访问 file: URL，未直接自动化验证双击文件路径。
代码无外部资源；若某个浏览器限制离线原生捕获，会保留 SVG 路径并显示状态。
面向当前静态底板设计；长页面超出纹理预算、视频和复杂动态布局需另行设计。
